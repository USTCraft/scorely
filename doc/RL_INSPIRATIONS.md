# 积分设计灵感：强化学习视角

> 来源：2026-08-13 设计讨论（惩罚榜启发自 RL 奖励信号概念）
> 定位：为**默认积分策略整体规划**与后续 Phase 提供候选思路，非承诺需求。
> 状态标记：🟢 可直接纳入 / 🟡 需机制前置 / 🔴 需事件感知 / ⚪ 概念启发

---

## 一、RL 框架 → Scorely 映射

| RL 概念 | 类比 | Scorely 对应 |
|---|---|---|
| 奖励信号（reward signal） | 每步的标量反馈 | 各规则积分（统计累计 × 权重 / 里程碑档位 / 进度一次性） |
| 奖励塑形（shaping） | 稀疏→密集 | 探索榜 tiers 里程碑（每 10km 一档）已是塑形 |
| 折扣因子 γ | 远期奖励打折 | （无）终身累计不衰减；赛季制可引入周期归零 |
| TD 误差 / 预测偏差 | 实际−预期奖励 | 连击 / 首通加成（需实时事件） |
| 奖励饱和（log/sqrt） | 长尾压缩、防刷 | **未实现**——线性模式下刷分收益恒定 |
| 内在动机 / 好奇心 | 探索未见状态 | 探索广度（已解锁统计项计数）——幂等可算 |
| 奖励归一化 | 各维可比 | **未实现**——探索榜数值天然碾压进度榜 |
| 相对表现 / baseline | 与基线比而非绝对值 | 进步榜（周 Δ 排行，需快照） |
| 奖励发放频率 | 行为→反馈延迟 | 全量刷新 5 分钟；在线高频 + 离线低频可分离 |
| 合约设计 / Goodhart | 指标成为目标即失效 | 见第四节检查表 |
| episode / 赛季 | 回合归零 | 赛季榜（新玩家冷启动友好） |

## 二、可落地思路

### A. 立即可用（幂等全量重算可实现）🟢

1. **饱和计分模式**：新增 `mode: log/sqrt`（如 `log(1+值)`、`sqrt(值)`），替代线性——
   击杀 1000 与 10000 的分差不该是 10 倍。系统性抑制刷分。
   - 落地：ScoringRule 扩展第三种计分模式，配置经 Phase 8 config.json 暴露。
2. **探索广度奖励**：`已解锁统计项数量 × 单值`（任何 >0 的统计项 = 已解锁）。
   首次钓鱼、首次附魔、首次造访维度均计入——**无需历史状态，幂等可算**。
   - 落地：新规则变体或 stat 规则扩展，全量重算天然支持。
3. **奖励尺度归一化**：各榜对总榜贡献可比化（对数压缩或按达成率折算），
   防单榜（如探索）因数值大而主导总榜。

### B. 中期（依赖 Phase 8.1 单玩家刷新机制）🟡

4. **分层刷新频率**：在线玩家高频（仅内存读取，如 30s）、离线玩家低频（随定时 5 分钟）。
   缩短"行为→分数"感知延迟，强化奖励关联（RL：即时奖励关联强）。
   - 落地：单玩家重算机制的自然延伸；不破坏全量幂等兜底。
5. **进步榜（相对表现）**：每周分差 Δ 排行（"本周进步最快"）。
   - ⚠️ 与"不持久化积分快照"的决定冲突：Δ 需要周期快照，需重新评估。

### C. 远期（需事件感知，Mixin 预留的"进度完成事件日志"）🔴

6. **连击 / streak 加成**：连续完成进度不中断 → 奖励递增（TD 误差式）。
7. **首次接触奖励**：首次到达新生物群系 / 维度给探索分（需位置事件）。
8. **PvP 竞争对称**：击杀玩家加权（高风险高回报）+ 死亡重罚——惩罚榜（Phase 10）
   落地时可顺手纳入击杀加权，保证奖惩对称。

### D. 概念层启发 ⚪

9. **赛季榜**（episode 重置）：终身档案之外可选周期归零榜——解决新玩家冷启动。
   决策点：是否引入，影响 players.json / 榜单结构。
10. **Goodhart 检查表**（见下节）：默认策略设计的必修课。

## 三、优先级建议

1. **A1 饱和计分模式**——治刷分，性价比最高；并入"默认积分策略整体规划"
2. **A2 探索广度奖励**——新玩法维度，全量重算直接支持
3. **D9 赛季榜**——先做决策（要不要），影响配置结构
4. **B4 分层刷新频率**——Phase 8.1 实现时顺手评估
5. **A3 奖励归一化**——与默认策略一起定

## 四、Goodhart 检查表（默认策略设计准则）

> "当分数成为目标，它就不再是好分数。"——RL 奖励设计核心教训。

每条规则上线前检查：

- [ ] **可廉价刷取吗？** 挂机走路 / 蹲刷怪塔是否收益过高 → 用 cap / 饱和计分 / 效率惩罚
- [ ] **奖惩对称吗？** 给击杀加权就必须给死亡惩罚，否则玩家无风险刷分
- [ ] **多榜可比吗？** 各榜对总榜贡献是否被数值量级扭曲 → 归一化 / 对数压缩
- [ ] **边际递减了吗？** 重复同一行为的边际收益是否递减 → 阶段/饱和模式
- [ ] **与核心语义一致吗？** 进度档案是"终身成就"——衰减/赛季等设计是否改变该语义（需明示）

## 五、人工评审积分（RLHF：人类反馈）

> 来源：2026-08-13 讨论——不可量化内容（建筑 / 交通 / 红石机器等）的计分方式
> 状态：🟡 需机制前置（依赖 Phase 8 ConfigManager 持久化：原子写 + 脏标记）

**核心判断**：统计项无法感知开放创作（建筑美学、机械效率、交通设计），只能由 Admin 人工评审——
RL 对应 **RLHF**（人类反馈强化学习）：奖励无法从环境自动推导时，由人类提供奖励信号。

**双轨积分架构**（D2 的唯一非幂等例外）：

```
自动分（stat / advancement）→ 幂等全量重算，可推导
人工分（manual 规则）       → Admin 授予，唯一必须持久化的积分状态
总分 = 自动分 + 人工分
```

**设计要点**：

1. **规则模型**：`ScoringRule` 新增 `type: "manual"`（无 matchers / 无计分逻辑），如
   `{ "id": "building", "displayName": "建筑榜", "type": "manual" }`；引擎对 manual 型不参与重算
2. **持久化**：`manual_scores.json` —— `uuid → ruleId → [{score, reason, by, time}]`
   （明细留痕，可追溯评审主观性）；复用 ConfigManager 原子写 + 脏标记机制
3. **命令**：`/scorely admin award <player> <rule> <score> <reason>`；`/scorely score` 展示人工分明细
4. **防误操作**：单次 |score| 上限 + reason 必填
5. **引擎合并**：重算自动分 → merge 人工分 → 缓存快照；榜单 / 总榜自然包含人工分
6. **评审流程 v2（可选）**：`/scorely submit`（玩家提交作品 + 坐标/文字）+ `/scorely admin review`
   （评审队列，给分或拒）——更像服务器活动，先做直接 award

**架构影响**：D2"纯幂等重算"出现唯一例外——需明确定位"自动分重算 + 人工分持久化"双轨，
人工分严禁混入重算链路（重算只覆盖 stat/advancement 型）。

### 5.1 外部事件联动（社会奖励）

> 来源：2026-08-13 讨论——其他模组的社交功能（如"向某人表示仰慕"）如何统计计分
> 状态：🟡 需机制前置（manual_scores 持久化，Phase 8 之后）

**核心洞察**：外部事件计分 = **机器授予的授予分**——与人工评审积分同属"无法从统计数据推导、
必须由 Scorely 持久化"的状态，区别仅在授予者：

```
授予型积分（manual）
  ├── 授予者 = Admin      → admin award 命令
  └── 授予者 = 外部模组    → 事件回调 / 对方调用 Scorely 公开 API
```

**无需架构调整**，双轨（自动分幂等 + 授予分持久化）天然容纳，只需：

1. `manual_scores.json` 记录加 `source` 字段（admin / 外部模组 ID）
2. Scorely 公开授予 API：`grant(player, rule, score, source, detail)`
3. manual 语义推广为"授予型"（人工或外部来源）

**联动形态**（按优先级）：

| 场景 | 方式 | 依赖 |
|---|---|---|
| 对方公开事件（Fabric API 事件） | Scorely 注册回调 → `grant()` | 无 Mixin，普通注册 |
| 对方无事件但愿意集成 | 对方调用 Scorely 公开 API | fabric.mod.json `suggests` 软依赖 |
| 对方完全不配合 | Mixin 拦截对方逻辑（compat 层） | 版本敏感，最后手段 |

**风险设计**：

- 事件重复计数：对方在登录时重放历史事件会重复计分 → 按 `(source, eventId)` 去重，或只接受实时事件
- 崩溃丢失：事件计数落盘前崩溃 → 每次授予立即落盘（频率低，复用原子写）

**RL 视角**：这是**社会奖励**（social reward）——他人给予的奖励信号；与惩罚榜（负面信号）、
探索奖（内在动机）构成完整奖励光谱。
