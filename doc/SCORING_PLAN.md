> 定位：默认积分策略 + 预置榜单重做的规划文档（spec 驱动，讨论产物）
> 状态：进度/战斗/工艺/探索/惩罚已定；广度默认不启用；**全部榜单讨论完成**
> 关联：PLAN.md（路线图/实施注记）；本文档只收设计决策

## 1. 对齐原则

- **进度榜为基准**：先定进度榜赋分，其他榜满分向进度榜基准对齐（用户决策，2026-08-13）
- 对齐目的：各榜满分量级一致，总榜与分榜的含金量可横向比较

### 1.1 单榜积分上限（已定 2026-08-13）

- **机制**：`ScoringRule` 新增 `maxScore`（**显式满分**，规则配置的最大值，0 = 不限）；
  自然积分 = 全部命中条目计分之和（不设 cap 时各条目独立过档累加），
  **榜积分 = min(自然积分, maxScore)** 截断
- 与单条目 `cap` **独立生效**：cap 管单条目，maxScore 管整榜
- **上限值**：统一 **800**（用户拍板，2026-08-13；初定依据为进度榜 ~2170 的 1/3，
  进度榜调值至 ~3420 后**保持 800 不变**，与进度榜满分上限解耦，作为独立整数上限）
- **语义边界**（用户澄清 2026-08-13）：maxScore 是显式指定的最大值，**不是设计目标**——
  档位按自然频度设计，各统计口径之和可超过 800（如 1000+），800 只做最终截断，
  不得为了凑 800 而压低档位
- 适用范围：战斗/工艺/探索/广度等通配型榜均设 800；进度榜不设（进度有限，天然封顶 ~3420）
- 实施影响：ScoringRule 字段 + Gson 配置 + ConfigManager 校验 + 引擎两处截断 + lang 展示；
  缺省 0/null = 不限，兼容既有配置
- 设计含义：通配型榜为“量+广度”双驱动且无自然上限，maxScore 保证各榜满分统一 800，
  防刷子玩家（全方块收集/刷怪塔）头部失控；触顶后玩家转向其他榜继续游戏

### 1.2 总榜口径（已定 2026-08-13）

- **总榜 = 各分榜积分的加权和**，默认权重均为 1（用户拍板）
  - `总榜分 = Σ(分榜积分 × weight)`
- 权重字段：`ScoringRule.weight`（默认 1，缺省 0/空 = 1，兼容既有配置）；
  实施影响：字段 + Gson + ConfigManager 校验 + 引擎总榜聚合乘权重
- 惩罚榜负分**直接计入**总榜（扣分拉低总榜）；进度榜不设 maxScore、天然高位（~3420）如实计入
- 设计含义：各分榜满分统一 800（见 1.1）后，加权和量级横向可比——
  “其他榜满分向进度榜基准对齐”的决策正是为总榜加权提供可比基础

### 3.1 工艺榜 craft（已定 2026-08-13）

> 命名：craft（工艺，用户 2026-08-13）；旧 id `mining` 弃用，lang 键 `scorely.rule.mining` → `scorely.rule.craft`；
> 旧 config.json 中用户自定义 rules 不受影响（id 为用户侧定义）

- **口径**：`minecraft:mined`（挖掘）+ `minecraft:used`（使用/放置）+ `minecraft:crafted`（合成）
- 不纳入（用户 2026-08-13 拍板）：`broken`（工具损坏）、custom 加工类
  `enchant_item`（附魔）、`interact_with_furnace/blast_furnace/smoker`（烧炼）、
  `interact_with_brewingstand`（酿造）、`interact_with_smithing_table`（锻造）、picked_up/dropped（非建造动作）
- **可统计项目**：mined = 全部注册方块，used/crafted = 全部注册物品；
  26.2 条目数运行时校准（CompatHelper 遍历时统计，参考注释量级约 5000 项）
- 技术要点：StatsType 三键已定义；matcher 支持 `*` 通配与逐项独立配置；
  现状 mining 规则仅 mined 单类型 ×1.0 / cap 1000（默认），需重构
- **数值定稿**（纯阶段奖励，cap=0，榜级 maxScore=800 显式满分）：

  | matcher | tiers（threshold→value） | 单条目满分 |
  | --- | --- | --- |
  | `minecraft:mined` / `*` | 1000→5、5000→15、20000→30、50000→50、100000→100 | 200 |
  | `minecraft:used` / `*` | 500→5、2000→15、10000→30、20000→50、50000→100 | 200 |
  | `minecraft:crafted` / `*` | 100→5、500→15、2000→30、5000→50、10000→100 | 200 |

  量级验证（自然积分按档位展开，不迁就 800）：休闲 3 挖×2 万+3 放×1 万+5 合×1 千 ≈ 105；
  中活跃 6 挖×2 万+5 放×1 万+8 合×1 千 ≈ 195；
  活跃 10 挖×5 万+8 放×2 万+12 合×5 千 ≈ 1500 → min(1500, 800) = **800**
  档位按自然频度拉开：挖掘十万级 / 放置万级 / 合成千级；单条目满分统一 200
（用户拍板 2026-08-13：档位量级与 5 档结构照此定稿）

### 3.3 战斗榜（已定 2026-08-13）

用户决策：纯阶段奖励；damage_dealt 不纳入；killed_by 不进战斗榜（留惩罚榜）；规则 id 保持 `combat`。

| matcher | tiers（threshold→value） | cap | 单条目满分 |
| --- | --- | --- | --- |
| `minecraft:killed` / `*` | 100→10、500→30、1000→50、2500→100、5000→200 | 0（不封顶） | 390（5000 击杀/实体） |
| `minecraft:custom` / `minecraft:player_kills` | 5→20、20→50、50→100、100→200 | 0（不封顶） | 370 |

- 计分语义：每条目独立过档累加（引擎已支持），多实体击杀量 + 击杀广度双驱动
- 量级：活跃玩家覆盖 8~10 种常见怪各 500~2000 → 自然积分 500~1100，min(自然, 800) = 500~800；
  PVP 玩家 player_kills 100 → +370；典型全勤玩家 → 600~800
- 上限校验：maxScore=800 下，killed 全满（10 种怪 ×390）→ 截 800；
  典型组合 killed 5 种×2000 + player_kills 50 → 250+200+100=550 ~ 760，落在 800 内（见 1.1）
- 实施要点：tiers 模式必须显式配 `cap=0`（规则级默认 cap=1000 会封掉 5000 档，导致最高档永远不触发）
- 不纳入：damage_dealt（与 killed 强相关，防刷怪收益放大）、killed_by（负分候选）

- 规则 id：`explore`；显示名：探索
- **口径**（固定键逐项配置，matcher 仅支持整 path 通配，无后缀通配）：
  - 距离类 12 键（`minecraft:custom` / `…_one_cm`，divisor=100000 cm→km）：
    walk / sprint / fly / swim / boat / minecart / horse / pig / strider / happy_ghast / nautilus / aviate
  - 开箱/钓鱼类 5 键（次数）：open_chest / enderchest / shulker_box / barrel / fish_caught
- 剔除（用户拍板）：crouch_one_cm（潜行）、inspect_dropper / inspect_hopper / inspect_dispenser
- 生物群系不可统计：26.x 官方统计无生物群系计数键，原占位方案（群系列表 +1/个）废弃
- **数值定稿**（纯阶段奖励，cap=0，榜级 maxScore=800 显式满分）：

  | 组 | divisor | tiers（换算后 threshold→value） | 单条目满分 |
  | --- | --- | --- | --- |
  | 距离 12 键 | 100000 | 5km→30、40→50、100→80、400→120、800→200 | 480 |
  | 开箱/钓鱼 5 键 | 1 | 50→30、200→70、500→120、1000→200、2000→300 | 720 |

- 量级验证（自然积分）：休闲 走 40km+飞 100km+开箱 200 ≈ 340；
  活跃 走 100km+飞 400km+游 50km+船 100km+开箱 1000+钓 300 ≈ 1200 → min(1200, 800) = **800**；
  肝帝全键高位 → 自然 2000+ → 截 **800**
- 设计要点：开箱单键满分 720 > 距离单键 480（搜刮/翻箱是探索主旋律，权重更高）；
  5km / 50 次起档，新手期即有反馈；门槛 800 截断与其余通配榜一致

### 3.5 广度榜（默认不启用 2026-08-13）

- 用户决策：默认配置不使用广度榜（2026-08-13）
- 原占位口径：全部统计条目值 >0 计数（元统计，~5000 条上限）
- 技术现状：引擎无“统计条目解锁计数”模式（现有规则只做匹配求和）；PLAN.md Phase 12 规划的
  `mode=count` 扩展即为该能力（每解锁一项 +multiplier，tiers/cap/divisor 忽略），实施后
  自建广度榜技术可行（statType 通配支持）；**默认仍不预置进 DefaultRules**（用户拍板）

### 3.6 惩罚榜（口径已定 2026-08-13）

> 定位：负积分榜（Phase 10 规划）；扣分越多排名越前（sort=asc）

- **口径定稿**（用户拍板）：
  - `minecraft:custom` / `minecraft:deaths`（死亡次数，全量含 PVP 被杀）
  - `minecraft:killed_by` / `*`（被击杀归因，通配逐实体，**豁免 `killed_by/minecraft:player`**）
  - `minecraft:custom` / `minecraft:damage_taken`（承受伤害）
  - **PVP 击杀者特化**：`minecraft:killed` / `minecraft:player`（击杀玩家次数）负分口径
- 排除：drop、fall_one_cm、防御类、时长类
- **PVP 计分原则**（用户 2026-08-13）：
  - 被击杀一方：**按 deaths 正常计负分**（不再豁免）；killed_by/player 豁免避免双计
  - 击杀一方：**特化负分口径**（killed/minecraft:player 扣分），与战斗榜 player_kills 正分双轨并存
- **封底机制**（用户 2026-08-13）：负分设置封底（-800）防滥用（自杀刷分/无限叠加）；
  原定 PVP 击杀不封底，**同日重新纳入封底**（统一 -800，用户）
- 技术要点：maxScore 负值语义 = 封底下限（score = max(自然, maxScore)），全榜统一截断；
  Phase 10 放开引擎/缓存正分过滤；killed_by/* 通配逐实体独立计分求和

### 3.7 惩罚榜数值（已定 2026-08-13）

> 用户拍板：按 tiers；各项分度改小（deaths 3 起 / killed_by 1 起 / damage_taken 50 起）；
> killed_by 较少计算负分、由 deaths 主担；档位**边际递增**（增量随阈值加速）；指定最大负值封底；
> **档位分值步进 5**（不用 -1/-2 等小值）

| 键 | tiers（threshold→value，累加）              | 满档 | 边际增量 |
| --- |---------------------------------------------| --- | --- |
| `custom`/`deaths` | 3→-10、10→-15、15→-20、20→-40、30→-80       | -165 | 10/5/5/20/40 |
| `killed_by`/`*`（豁免 player） | 1→-5、10→-10、50→-20、200→-35               | -70/条目 | 5/10/10/15 |
| `custom`/`damage_taken` | 50→-5、100→-10、300→-20、1000→-35、5000→-55 | -125 | 5/10/15/20 |
| `killed`/`minecraft:player`（PVP 特化） | 1→-20、5→-40、10→-60、15→-80、50→-100        | -300 | 20×4 |

- 量级验证：新手（10 死/10 被杀/500 HP）≈ -75；活跃（50 死/40 被杀/5 万 HP）≈ -305；
  资深（100+ 死/100+ 被杀/20 万 HP）≈ -325；肝帝（大量叠加）触 -800 封底
- PVP 击杀者叠加：10 杀 -120、50 杀 -300（纳入封底，与普通惩罚合计受 -800 限制）
- 封底：规则级 maxScore=-800（负值语义 = max(自然, -800)），全榜统一（含 PVP 击杀）
- 分值调整：用户 2026-08-13 手动微调——deaths 阈值收窄至 30 封顶（满 -165）、
  damage_taken 阈值大幅下调（5000 HP 即满 -125）、PVP 击杀改为 1→-20 起（满 -300）
